## 目標

Ollama/Pythonを別途インストールせず、PC・Android・iOSで資料を検索し、根拠を確認しながら対話します。共通コアと各プラットフォームのアプリを使い、全機器で同じバイナリを使うわけではありません。

既存ハブの機器に合うモデル選択・インストールの流れを保ち、個人資料の検索と根拠付き対話を1つのアプリで提供します。ユーザーによるエンジンサーバー設定や開発ツールの導入は不要にします。

## ユーザーと解決する課題

- 個人・研究者：文書や写真を外部に送らず、自然言語で探して根拠を確認する。
- ローカルAI利用者：モデルのファイル容量と実際のメモリ要件を区別し、自分の機器で検証されたモデルを導入する。
- 開発者：将来の任意ローカルAPIで同じ実行契約を利用する。Narmer連携要件は互換性検証資料として継承する。

## 必須プラットフォームと対応の意味

Windows・macOS・Linux・Android・iOS/iPadOSのインストール型アプリが必須です。スマートフォンだけでなくAndroidタブレット・iPadの画面、ファイル選択、アプリ復帰も検証します。ブラウザー単独実行は将来候補であり、Web技術を使ったPC UIとブラウザー内での独立推論は区別します。

| 対象 | 初回共通リリースの基準 | 追加検証対象 |
|---|---|---|
| Windows | x86_64 | ARM64 |
| macOS | Apple Silicon arm64 | Intel x86_64 |
| Linux | x86_64、N0で決める基準ディストリビューション | arm64・他ディストリビューション |
| Android | arm64、スマートフォン・タブレット | 追加メーカー・アクセラレーター |
| iOS/iPadOS | arm64、iPhone・iPad | 追加の機器世代 |

アーキテクチャの優先順位は設計上の既定値です。最低OS・RAM・保存容量・LinuxディストリビューションはN0で実測して固定します。全OS対応は全旧機種・CPU・モデルを保証する意味ではありません。追加構成は未検証と表示し、正式対応と宣伝しません。

各必須プラットフォームはモデル準備後、他PC・サーバー・クラウドなしで資料追加、文書・写真検索、テキスト根拠付き対話、保存・復旧を行います。写真の意味検索は必須です。写真内容からの回答は生成モデルのvisionまたは実際のOCR/キャプションの有無を表示します。同一モデル・速度・アクセラレーターは必須ではありませんが、機能制限はインストール前に案内します。

## 初回リリースの基本想定

- 個人用・ローカル優先、韓国語検索品質を優先検証
- PDF・Markdown・TXT・写真の追加と差分索引
- 意味検索結果から元のページ・写真を開く
- 検索根拠に基づく対話と有効な出典表示
- 各プラットフォームで検索モデル1つ・生成モデル1つを検証
- オフライン利用、キャンセル・終了・再起動からの復旧

## 主な画面と利用フロー

1. **開始・モデルセンター：** 機器診断 → 検証済み検索/生成パッケージ推薦 → 容量・ライセンス確認 → インストールまたはローカル取り込み。推定値と機器実測値を区別します。
2. **プロジェクト・資料：** 作成 → ファイル・写真選択 → 索引進行・取消・再開 → 失敗資料だけ再試行。
3. **検索：** 自然言語検索 → 文書ページ・写真結果 → 原本表示 → 選んだ根拠で質問。
4. **対話：** 一般対話とプロジェクト根拠付き対話を区別。token・出典・停止・部分回答状態を表示し、根拠不足を明示。
5. **設定・機器：** モデル・資料の保存容量、利用可能機能、検証状態、ローカルデータ削除。

PCはキーボードと広い画面、モバイルはタッチとOSファイル/写真選択を使用します。読み上げラベル・文字サイズ変更・キーボード移動・状態のテキスト表現を共通UX基準とします。スマートフォン画面の引き伸ばしをタブレット検証の代用にしません。

## 後続範囲

音声・動画の区間検索、元の時間位置から再生、追加モデル、MCP、任意の信頼ノードとプロジェクト移行。

Qwen/Gemma/DeepSeek/Mistral/Phi/gpt-ossは拡張評価候補として継承します。過去のOllama tag・カタログ登録・他エンジンでの成功はnative対応の証拠にしません。各プラットフォームでartifactと生成/embedding capabilityを個別検証します。MLXはmacOS専用adapter候補で、共通コアの必須依存ではありません。

## 対象外

初期モデル学習・fine-tuning、音声・動画生成、自動クラウド送信、自動機器同期、全Hugging Faceモデルの自動変換、モバイルでの大型モデル実行保証。

## 完了基準

Ollama/Python未導入のPC 3 OSとAndroid/iOS実機で基本検索・対話を検証します。最低OS・機器、SDK/artifact、性能予算はN0実測で決定します。詳細な契約とgateは[アーキテクチャ](architecture.ja.md)に従います。

N1はPCプレビュー、N2が初回共通正式リリースです。必須プラットフォームの1つでもgate未通過なら全対応完了とは表示しません。韓国語検索Recall@5・遅延・メモリ目標とfixtureは設計11章に従い、数値は達成結果ではなく目標です。

## 未決事項

- ブラウザー単独実行の時期、別途の保存・権限・offline方針
- 最低OS・機器・Linuxディストリビューション、追加CPUの正式対応時期
- 初回生成モデル、固定SDK/artifact、配布形式・経路
- 拡張の順序、自動同期の必要性

未決事項は想定を明記して進めます。実測失敗を理由に必須プラットフォームを黙って除外したり、リモート実行に置き換えたりしません。
