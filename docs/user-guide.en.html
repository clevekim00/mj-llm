A little guide to local AI

Inside your Mac,
two little AI helpers.

One finds similar things.
One answers in words.

Try it now · Apple Silicon Mac

For now, we are checking that it works.

We test with prepared sentences, a red picture, and a math question.
An app for free chat or searching your own files is not available yet.

The finder

It turns words and pictures into a map of numbers.
Similar meanings sit close together on the map.

Model: EmbeddingGemma 2
The talker

It reads a question and writes an answer.
This time, we ask “2 + 2?”

Model: Qwen3-0.6B

1

Set up your workbench.

Terminal is a window where you type requests to your computer.

⌘ + Space → “Terminal”Rust 1.95.0Xcode developer tools

These tools are needed for this developer preview. Start in this Mac folder.

cd ~/Project/mj-llm
rustc --version
cargo --version
xcrun clang++ --version
If you do not have the project yet

Run this in your chosen work folder. If a folder with this name already exists, open it instead of cloning again.

git clone https://github.com/clevekim00/mj-llm.git
cd mj-llm

command not found means the developer tools need setup first. Use a Mac with Rust and Xcode developer tools installed.

Keep using this Terminal window. The first build may need internet to fetch development dependencies.

2

Get three boxes.

1 engine + 2 models

The engine makes things run.
The models hold what the helpers learned.

About 1.05GB to downloadInternet for initial setup

Allow extra space for unpacking and building.
Skip this step if you already have these exact files.

Show download commands

Copy, paste into Terminal, and press Enter. This group stops if file verification fails.

(
set -e
mkdir -p downloads/n0 models .mj-llm/n0
curl -fL https://github.com/google-ai-edge/LiteRT-LM/releases/download/v0.18.0/CLiteRTLM_mac.xcframework.zip -o downloads/n0/sdk.zip
printf '%s  %s\n' '5f6ee68d95eeccb084c6e66d5ee47255e3020fa0fb29696dd0301ae26d6cfb4f' 'downloads/n0/sdk.zip' | shasum -a 256 -c -
unzip -oq downloads/n0/sdk.zip -d downloads/n0/sdk
curl -fL https://huggingface.co/litert-community/embeddinggemma-2-text-vision-440m-litert-lm/resolve/e301f74d5551b0c2641bd5cb4652a76239d5c5f8/embeddinggemma-2-text-vision-440m.litertlm -o models/embeddinggemma-2-text-vision-440m.litertlm
curl -fL https://huggingface.co/litert-community/Qwen3-0.6B/resolve/a3c5d805ae362dff7f580bc25f2dfb9a5a7eaa76/Qwen3-0.6B.litertlm -o models/Qwen3-0.6B.litertlm
)

The engine fingerprint (SHA-256) must match before unpacking. The run tool checks both model fingerprints. Model terms come from each distribution page.

3

Wake the helpers.

First, build the run tool. “Finished” means it is ready!

Build and setup commands
export MJ_LITERT_SDK_DIR="$PWD/downloads/n0/sdk/CLiteRTLM_mac.xcframework/macos-arm64_x86_64"
export DYLD_LIBRARY_PATH="$MJ_LITERT_SDK_DIR"
cargo build -p mj-llm-n0 --release --features native-macos --locked

First, the finder

It reads prepared Korean sentences and a red picture.
You do not need to select your own photos.

target/release/mj-llm-n0 probe models/embeddinggemma-2-text-vision-440m.litertlm .mj-llm/n0/embedding-cache

Next, the talker

It answers the prepared question “2 + 2?”
This command runs a fixed test, not a free-chat session.

target/release/mj-llm-n0 generate-probe models/Qwen3-0.6B.litertlm .mj-llm/n0/generation-cache

Wait for one helper to finish before running the next command. In a new Terminal window, return to the project folder and repeat the build and setup commands.

Run the complete test sequence

This runs automated tests in several groups, then a final code check. Everything must finish without errors.

bash scripts/test-n0-macos.sh downloads/n0/sdk/CLiteRTLM_mac.xcframework/macos-arm64_x86_64 models/embeddinggemma-2-text-vision-440m.litertlm models/Qwen3-0.6B.litertlm

Recorded results: 12 ordinary tests + 3 real-model tests passed. The real-model section shows 3 passed; 0 failed.

Stuck? Start here.

It says cargo is missing

Rust tools are not ready. Start with the tool version checks in step 1.

A file cannot be found

pwd shows your current location. Run inside the project folder. Both models belong in the models folder.

A native SDK or dylib error appears

Repeat step 3 setup commands in the same Terminal window. If the SDK folder is missing, check step 2.

A hash, checksum, or verification error appears

The file differs from the pinned version. Download it again from step 2. Do not skip verification.

I see WARNING

It may be an SDK diagnostic. Check the final status. Ending with failed or an execution error is not success.
