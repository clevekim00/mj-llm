A little guide to local AI

Macの中に、
小さなAIが2人。

1人は似たものを探し、
1人は言葉で答えます。

今試せる環境 · Apple Silicon Mac

今は「ちゃんと動くかな？」を確かめる段階です。

用意した文・赤い絵・算数の問題で試します。
自由に会話したり、自分のファイルを探すアプリ画面はまだありません。

探すお手伝い

文や絵を「数字の地図」に変えます。
意味が似ていると、地図でも近くなります。

モデル名：EmbeddingGemma 2
話すお手伝い

質問を読んで、答えを作ります。
今回は「2 + 2？」と聞きます。

モデル名：Qwen3-0.6B
01準備する023つの箱を受け取る03お手伝いを起こす04成功を確かめる
1

作業台を準備しよう。

ターミナルは、文字でパソコンにお願いする窓です。

⌘ + Space →「ターミナル」Rust 1.95.0Xcode開発ツール

開発用の体験に必要な道具です。このMacのフォルダーから始めます。

cd ~/Project/mj-llm
rustc --version
cargo --version
xcrun clang++ --version
プロジェクトがまだない場合

作業用フォルダーで実行します。同名のフォルダーがあれば、再取得せずその中へ移動します。

git clone https://github.com/clevekim00/mj-llm.git
cd mj-llm

command not foundと表示されたら、開発ツールの準備が必要です。RustとXcode開発ツールを導入したMacで進めてください。

続きも同じターミナルで行います。初回ビルドは開発部品の取得にネット接続が必要な場合があります。

2

3つの箱を受け取ろう。

エンジン1つ + モデル2つ

エンジンは動かす道具、
モデルはお手伝いが学んだ内容です。

ダウンロードは約1.05GB初回準備にネット接続

展開とビルドのための空き容量も必要です。
同じファイルがあれば、この手順は飛ばせます。

ダウンロードのコマンドを開く

コピーしてターミナルに貼り、Enterを押します。ファイル確認に失敗するとこの処理は止まります。

(
set -e
mkdir -p downloads/n0 models .mj-llm/n0
curl -fL https://github.com/google-ai-edge/LiteRT-LM/releases/download/v0.18.0/CLiteRTLM_mac.xcframework.zip -o downloads/n0/sdk.zip
printf '%s  %s\n' '5f6ee68d95eeccb084c6e66d5ee47255e3020fa0fb29696dd0301ae26d6cfb4f' 'downloads/n0/sdk.zip' | shasum -a 256 -c -
unzip -oq downloads/n0/sdk.zip -d downloads/n0/sdk
curl -fL https://huggingface.co/litert-community/embeddinggemma-2-text-vision-440m-litert-lm/resolve/e301f74d5551b0c2641bd5cb4652a76239d5c5f8/embeddinggemma-2-text-vision-440m.litertlm -o models/embeddinggemma-2-text-vision-440m.litertlm
curl -fL https://huggingface.co/litert-community/Qwen3-0.6B/resolve/a3c5d805ae362dff7f580bc25f2dfb9a5a7eaa76/Qwen3-0.6B.litertlm -o models/Qwen3-0.6B.litertlm
)

エンジンの指紋（SHA-256）が合ってから展開します。モデル2つの指紋は実行ツールが確認します。利用条件は各配布ページに従います。

3

お手伝いを起こそう。

まず実行ツールを作ります。「Finished」が出れば準備完了！

実行準備のコマンド
export MJ_LITERT_SDK_DIR="$PWD/downloads/n0/sdk/CLiteRTLM_mac.xcframework/macos-arm64_x86_64"
export DYLD_LIBRARY_PATH="$MJ_LITERT_SDK_DIR"
cargo build -p mj-llm-n0 --release --features native-macos --locked

まず、探すお手伝い

用意した韓国語の文と赤い絵を読みます。
自分の写真を選ぶ必要はありません。

target/release/mj-llm-n0 probe models/embeddinggemma-2-text-vision-440m.litertlm .mj-llm/n0/embedding-cache

次に、話すお手伝い

用意した「2 + 2？」に答えます。
このコマンドは動作テストです。自由な会話ではありません。

target/release/mj-llm-n0 generate-probe models/Qwen3-0.6B.litertlm .mj-llm/n0/generation-cache

1人が終わってから次のコマンドを実行します。ターミナルを開き直したら、プロジェクト内で実行準備のコマンドをもう一度行います。

4

この文字が出たら成功！

長い出力からstatusを探してください。

探すお手伝い ✓
"status": "embedding_smoke_passed"
話すお手伝い ✓
"status": "generation_smoke_passed"
記録された回答例：2 + 2 = 4

product_verified: falseは正常です。小さな動作テストには合格しましたが、アプリ全体の検証はまだという意味です。

まとめてテストしたい

自動テストのコマンドです。複数の結果と最後のコード検査が続き、最後までエラーなく終わる必要があります。

bash scripts/test-n0-macos.sh downloads/n0/sdk/CLiteRTLM_mac.xcframework/macos-arm64_x86_64 models/embeddinggemma-2-text-vision-440m.litertlm models/Qwen3-0.6B.litertlm

現在の記録：一般テスト12件 + 実モデルテスト3件に合格。実モデル部分では3 passed; 0 failedと表示されます。

困ったら、ここから。

cargoがないと言われる

Rust開発ツールが準備できていません。手順1のバージョン確認から始めてください。

ファイルが見つからない

pwdで現在位置を確認します。プロジェクト内で実行してください。2つのモデルはmodelsフォルダーに置きます。

native SDKやdylibのエラー

同じターミナルで手順3の準備コマンドを再実行します。SDKフォルダーがなければ手順2を確認します。

hash・checksum・verificationのエラー

取得ファイルが指定版と異なります。手順2のURLから取り直してください。検査は飛ばさないでください。

WARNINGが出る

SDKの案内の場合もあります。最後のstatusを確認します。failedや実行エラーで終わったら成功ではありません。

自分の質問や写真を使いたい

今のコマンドは固定の例だけで試します。自由な会話や個人資料の検索画面は今後の実装です。
