하나는 비슷한 것을 찾고,
하나는 말로 대답해요.

지금 따라하기 · Apple Silicon Mac

지금은 ‘잘 작동하나?’ 확인하는 단계예요.

준비된 문장·빨간 그림·산수 문제로 시험해요.
자유롭게 채팅하거나 내 파일을 검색하는 앱 화면은 아직 없어요.

찾는 도우미

글과 그림을 ‘숫자 지도’로 바꿔요.
뜻이 비슷하면 지도에서도 가까워요.

모델 이름: EmbeddingGemma 2
말하는 도우미

질문을 읽고 답을 만들어요.
이번에는 “2 + 2?”를 물어봐요.

모델 이름: Qwen3-0.6B
01작업대 준비02세 상자 받기03도우미 깨우기04성공 확인
1

작업대를 준비해요.

터미널은 컴퓨터에 글로 부탁하는 창이에요.

⌘ + Space → ‘터미널’Rust 1.95.0Xcode 개발 도구

개발용 체험에 필요한 준비물이에요. 이 Mac 폴더에서 시작해요.

cd ~/Project/mj-llm
rustc --version
cargo --version
xcrun clang++ --version
프로젝트가 아직 없다면

원하는 작업 폴더에서 아래를 실행해요. 같은 이름의 폴더가 이미 있으면 복제하지 말고 그 폴더로 들어가요.

git clone https://github.com/clevekim00/mj-llm.git
cd mj-llm

command not found가 나오면 개발 도구 준비가 먼저예요. Rust와 Xcode 개발 도구가 설치된 Mac에서 진행해 주세요.

아래 단계도 이 터미널에서 이어가요. 첫 빌드 때는 개발 부품을 받느라 인터넷이 필요할 수 있어요.

2

세 상자를 받아요.

엔진 1개 + 모델 2개

엔진은 작동 도구,
모델은 도우미가 배운 내용이에요.

약 1.05GB 다운로드처음 준비할 때 인터넷

압축을 풀 공간과 빌드 공간도 필요해요.
이미 같은 파일을 받았다면 이 단계는 건너뛰어요.

다운로드 명령어 펼치기

복사해서 터미널에 붙여 넣고 Enter를 눌러요. 파일 확인에 실패하면 이 묶음은 멈춰요.

(
set -e
mkdir -p downloads/n0 models .mj-llm/n0
curl -fL https://github.com/google-ai-edge/LiteRT-LM/releases/download/v0.18.0/CLiteRTLM_mac.xcframework.zip -o downloads/n0/sdk.zip
printf '%s  %s\n' '5f6ee68d95eeccb084c6e66d5ee47255e3020fa0fb29696dd0301ae26d6cfb4f' 'downloads/n0/sdk.zip' | shasum -a 256 -c -
unzip -oq downloads/n0/sdk.zip -d downloads/n0/sdk
curl -fL https://huggingface.co/litert-community/embeddinggemma-2-text-vision-440m-litert-lm/resolve/e301f74d5551b0c2641bd5cb4652a76239d5c5f8/embeddinggemma-2-text-vision-440m.litertlm -o models/embeddinggemma-2-text-vision-440m.litertlm
curl -fL https://huggingface.co/litert-community/Qwen3-0.6B/resolve/a3c5d805ae362dff7f580bc25f2dfb9a5a7eaa76/Qwen3-0.6B.litertlm -o models/Qwen3-0.6B.litertlm
)

엔진 파일의 지문(SHA-256)이 맞아야 압축을 풀어요. 두 모델의 지문은 실행 도구가 확인해요. 각 모델의 이용 조건은 배포 페이지를 따라요.

3

도우미를 깨워요.

먼저 실행 도구를 만들어요. ‘Finished’가 나오면 준비 끝!

실행 준비 명령어
export MJ_LITERT_SDK_DIR="$PWD/downloads/n0/sdk/CLiteRTLM_mac.xcframework/macos-arm64_x86_64"
export DYLD_LIBRARY_PATH="$MJ_LITERT_SDK_DIR"
cargo build -p mj-llm-n0 --release --features native-macos --locked

먼저, 찾는 도우미

준비된 한국어 문장과 빨간 그림을 읽어요.
내 사진을 고를 필요는 없어요.

target/release/mj-llm-n0 probe models/embeddinggemma-2-text-vision-440m.litertlm .mj-llm/n0/embedding-cache

그다음, 말하는 도우미

준비된 “2 + 2?” 질문에 답해요.
아래 명령은 자유 채팅이 아닌 작동 시험이에요.

target/release/mj-llm-n0 generate-probe models/Qwen3-0.6B.litertlm .mj-llm/n0/generation-cache

한 명이 끝난 뒤 다음 명령을 실행해요. 터미널을 새로 열었다면 프로젝트 폴더에서 ‘실행 준비 명령어’를 다시 실행해요.

4

이 글자가 보이면 성공!

긴 출력에서 status를 찾아보세요.

찾는 도우미 ✓
"status": "embedding_smoke_passed"
말하는 도우미 ✓
"status": "generation_smoke_passed"
기록된 답변 예시: 2 + 2 = 4

product_verified: false는 정상이에요. 작은 작동 시험을 통과했고, 전체 앱 검증은 아직이라는 뜻이에요.

전체 시험을 한 번에 하고 싶어요

자동 시험 명령이에요. 여러 묶음의 결과와 마지막 코드 검사가 이어져요. 마지막까지 오류 없이 끝나야 해요.

bash scripts/test-n0-macos.sh downloads/n0/sdk/CLiteRTLM_mac.xcframework/macos-arm64_x86_64 models/embeddinggemma-2-text-vision-440m.litertlm models/Qwen3-0.6B.litertlm

현재 기록: 일반 시험 12개 + 실제 모델 시험 3개 통과. 이 명령은 실제 모델 시험에서 3 passed; 0 failed를 보여줘요.

멈췄다면, 여기부터.

cargo가 없다고 해요

Rust 개발 도구가 준비되지 않았어요. 첫 단계의 도구 버전 확인부터 해 주세요.

파일을 찾지 못해요

pwd로 현재 위치를 확인해요. 프로젝트 폴더 안에서 실행해야 해요. 두 모델은 models 폴더에 있어야 해요.

native SDK 또는 dylib 오류가 나요

3단계 ‘실행 준비 명령어’를 같은 터미널에서 다시 실행해요. SDK 폴더가 없으면 2단계부터 확인해요.

hash · checksum · verification 오류가 나요

받은 파일이 정해진 파일과 달라요. 해당 파일을 2단계 주소에서 다시 받아요. 검사를 건너뛰지는 마세요.

WARNING이 보여요

SDK 안내 문구일 수도 있어요. 마지막 status를 확인해요. failed나 실행 오류로 끝나면 성공이 아니에요.

내 질문이나 내 사진을 넣고 싶어요

현재 명령은 정해진 예제로만 시험해요. 자유 채팅과 개인 자료 검색 화면은 다음 구현 단계예요.
